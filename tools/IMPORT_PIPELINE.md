# GLB 导入与显示

中键打开设置，点击 **导入 GLB 模型…**。首次转换可能需要数分钟，原角色保留；全部检查完成后启动新角色，确认新进程仍在运行才关闭旧角色。失败会保留原角色，日志位于 `artifacts/import-ui-进程号.log`。成功导入的模型与行为树路径保存在可执行文件旁的 `active-model.ini`，下次启动自动读取。

也可以在项目目录运行：

```powershell
./tools/import-model.ps1 -Source ./assets/Azusa.glb -Launch
```

省略 `-Launch` 只转换和验证，不切换角色。命令行 `--model`、`--behavior` 可覆盖已保存的角色。

## 流程

1. 检查 GLB 2.0、内嵌资源、动画名称和数据；记录原始文件 SHA-256，保留原文件副本。重名动作自动分配不冲突且符合长度限制的名称，索引与原名称映射写入 animation-names.json。
2. 筛选咖啡厅行为树引用的动作，以及战斗状态机所需的可用动作，再使用 Wiki 同版 Three.js 0.185.1 的插值器，以 60 Hz 采样，保留未动画化骨骼的默认变换。Hibiki 仍只需 Cafe_Idle、Cafe_Walk、Cafe_Reaction、Formation_Pickup；有完整战斗姿态的模型额外保留该姿态攻击、移动、技能、胜利、退场等动作。Exs_Cutin、Exs_Root、Public 等未使用动作不进入 Blender；原始 GLB 不变，清单与 battle 动作列表写入 animation-selection.json。旧的四动作精简模型需重新导入，新的筛选规则会使转换缓存自动更新。源文件预检查仍检查整个动作包，后续转换与验证只处理选中的动作。
3. 多套皮肤声明已有的共同骨架根节点，由 Blender 官方 glTF 导入/导出完成统一。没有手调关节位置或权重。
4. 将蒙皮叶节点移到场景根并清除其节点变换，避免 raylib 重复应用变换。按 glTF 蒙皮规则，这不改变蒙皮结果；骨骼、权重、inverse bind matrices 保持不变。存在子节点或节点 TRS 动画时明确拒绝，避免破坏层级。
5. 检查单蒙皮、选中动作的名称/时长、alpha MASK 与 cutoff、嘴型 morph 权重；按动作名生成 Groot2 XML。
6. 每个动作选取一个时间点在真实 raylib 中试渲染；Idle、点击、拖拽动作与 Three.js 做顶点数值对照。严重偏差阻止切换，较小偏差记录在报告中，由用户确认完整动画的视觉效果。

预检查失败也会记录源文件路径，并指出具体动作和问题（缺名、超长、时长无效等）。

缓存分为转换缓存和完整验证缓存。原文件、工具脚本/版本、程序或行为树变化会使相应缓存失效。产物、逐动作截图、姿态数据、版本与偏差报告存放在 `artifacts/imports/名字-哈希/`。

导入后在 Groot2 中增加动作时，需要该动作已经存在于转换模型；若新增了筛选清单之外的动作，先修改导入模板 `design/hibiki-cafe-attention.bt.xml` 再重新导入。当前不提供完整动作包转换模式。

## Azusa 与 Hibiki 的区别

Azusa 的子弹骨架需要声明与身体相同的已有根节点，Blender 才会导出一套蒙皮。导出后，Azusa 的网格仍挂在有旋转的骨架对象下面，因此需要第 4 步；Hibiki 原有产物的网格结构不同。

另在随项目提供的 `vendor/raylib-6.0/src/rmodels.c` 中修正了多根骨骼动画：对每个根应用它自己的父节点变换。原代码只处理第一个根，会使独立子弹根错位。升级 raylib 时需保留或重新验证此修正。此外，静态挂件会查找最近的祖先骨骼，而不限于直接父节点，使光环跟随头部；遇到带动画的中间节点不会跳过。没有按角色名字特殊处理骨架。

Iori 的两个骨架根还共用带动画的非关节父节点 `Bip001`。现在每帧从 glTF 动画读取完整祖先链的变换；不再只使用静态父节点。没有对角色名、骨骼位置或权重做特殊调整。动画时长也包含非关节节点和 morph 通道。新增 `gltf_animated_parent` 测试覆盖父节点平移/旋转/缩放、静态祖先、多个根以及不同动作间的默认值。

本次 Iori 4 个动作单点数值检查通过：Formation_Pickup 的 Three.js/raylib 最大顶点偏差由约 0.425 降至 0.00000104；Walk 约 0.00000100，Idle 约 0.000565，Reaction 约 0.000114。Hibiki/Azusa 三个代表动作回归未出现严重偏差；Hibiki 原有非均匀缩放/shear 的残余偏差仍保留。该检查不替代用户完整视觉验收。

## 范围与限制

- 当前针对 Wiki 这类自包含、有命名动画的 GLB；不是所有任意 GLB 都能自动适配。断开的骨架、必需扩展、超出 raylib 名称长度、立方插值 morph 等会明确失败。
- 没有匹配到 Walk 或 Click 时，不生成相应行为。默认角色眼睛朝向适配仍依赖模型骨骼命名和朝向约定。
- 每个动作的单点试渲染不等于完整动画验收。raylib 的非均匀缩放/shear 与未蒙皮挂件限制仍在；静态光环层级已补足，独立动画挂件仍需额外支持。
- 开发机使用已安装的 Node 和 Blender。转换不需要另装 Python（Blender 自带）。
- 菜单启动的进程可能没有终端中的 PATH。项目已在 `tools/runtime/node/node.exe` 放置 Node，导入器优先使用它；日志开头输出实际的 Node/Blender 路径，便于区分环境失败和转换失败。此目录不加入版本控制，发行时由打包脚本准备。
- `package-portable.ps1` 可把 Node、完整 Blender、Three.js、模型和程序放入一个目录，并优先使用随包运行时。完整 Blender 会使包明显增大。尚未在无开发环境的干净 Windows 机器验证，不能把当前开发目录称为免环境发行包。

## 轻量 UI 选择

- [raygui](https://github.com/raysan5/raygui)：单头文件，提供基础控件与样式，适合当前设置页；建议优先考虑。当前菜单是独立 Win32 窗口，替换仍需要接入绘制、输入和中文字体。
- [Dear ImGui](https://github.com/ocornut/imgui)：适合后续动作列表、资源预览与调试工具，官方有 Win32/OpenGL 后端，但接入量更大。

本次保留原生设置菜单，只加入导入入口，没有新加 UI 框架。

## 本轮程序性验证（2026-10-10）

- Azusa：1 套蒙皮、136 个骨骼、40 个动作、5 个 morph 网格；40 个动作均完成单时间点试渲染，20,905 次嘴型权重抽样检查通过。
- 三个代表动作（Cafe_Idle、Cafe_Reaction、Formation_Pickup）的源文件/转换文件顶点最大偏差约 0.00006243；转换文件的 Three.js/raylib 最大偏差约 0.00000050（模型单位）。此数据不替代完整动作的视觉验收。
- 两项 CTest 通过，含拐弯散步后直接朝最初起点返回。Hibiki 的窗口透明穿透、实体命中、置顶检查通过；原有背包 shear 偏差仍记录在回归报告。
- 通过实际文件选择器验证无效 GLB 保留旧角色、有效 GLB 使用缓存并启动新角色、旧角色随后退出；active-model.ini 记录 Azusa。
- 验证 Ctrl+Alt+Q 在原占用者释放后被新实例重新注册，关闭实例后释放。Ctrl+Alt+L 保留原有按键状态检测后备方案。
- 最终视觉效果由用户核对，当前报告状态为 ready_for_visual_review。

最终报告：`artifacts/azusa-import-result.json`。完整动作截图、日志及比较数据位于报告 model 字段对应目录。

## Iori 重名动作修正（2026-10-11）

用户提供的 Iori.glb 包含两个 Exs_Root。旧版导入器在预检查时直接拒绝；现在保留第一个名称，并将第二个自动改为 Exs_Root__2。只改缓存副本中的名称，不改动作数据、顺序或用户原文件。新模型同样适用，不以 Iori 名字做特殊判断。

运行 `node tests/import_names_tests.mjs` 可检查重名、已有后缀冲突、UTF-8 长度限制及文件数据保留。

## 导入进度

原生设置菜单显示步骤进度条、当前阶段、动作序号/总数及名称，以及已用时间。六步依次为：预检查、采样、Blender 转换、结构与面部校验、逐动作加载检查、动画数据对照。随后显示准备/启动新角色。缓存命中会跳过转换阶段。

百分比按处理步骤计算，不代表耗时比例；采样和 Blender 转换期间保留当前步骤进度，并用动态指示表示处理中。没有估算剩余时间。关闭菜单不影响导入，重新打开继续显示状态；失败保留原角色及错误描述。

进程间进度文件为 `artifacts/import-ui-进程号.progress`，菜单每 250 ms 读取一次。命令行可用 `-Progress 路径` 指定输出。已通过隔离阶段模拟和真实无效 GLB 的失败检查；未为此自动导入新角色。
