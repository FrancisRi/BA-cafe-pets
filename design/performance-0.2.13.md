# 0.2.13 多角色显示与诊断验证

## 改动

- 各角色先完成 GPU 绘制，再逐个读回各自的 FBO 并提交 Win32 窗口；仍在同一帧，无新增帧缓冲或额外一帧延迟。
- SSE2 转换 RGBA/BGRA；在处理相邻两行时直接扫描原有 2×2 Alpha 命中单元，减少循环和重复访存。
- 默认不创建日志目录、不打开日志文件、不采集逐帧性能数据、不启动挂起观察线程。`--diagnostics` 恢复这些排错功能。启动器把标准流指向 NUL，由核心程序独立决定是否开启诊断。

## 本机对照

相同的 Shiroko、Hoshino、Ibuki、Midori (Maid)、Natsu (Band) 列表；三角色取前三个。咖啡厅待机、缩放 0.55、线条模式 50%、2× SSAA，关闭散步、追踪、跟随和随机触发。每次独立启动并在加载后运行 20 秒，原用户数据不修改。
新旧版本均开启诊断以读取帧率：此对照反映渲染优化，不能把全部收益归因于关闭日志。帧率为最后四个约 3 秒窗口的算术平均，CPU 为启动 9 秒后的整机总 CPU 占用平均，内存为同期工作集。

| 角色数 / 版本 | 平均 FPS | 各统计窗口 FPS | CPU | 内存 |
|---|---:|---:|---:|---:|
| 5 / 旧版 | 42.1 | 38.5–46.1 | 6.91% | 203.7 MiB |
| 5 / 新版 | 47.4 | 44.3–50.6 | 7.18% | 203.7 MiB |
| 3 / 旧版 | 57.4 | 55.7–58.8 | 5.69% | 179.9 MiB |
| 3 / 新版 | 56.9 | 55.4–58.0 | 4.94% | 179.6 MiB |

五角色本轮约提升 12.5%，CPU 总占用略增，内存接近；三角色帧率基本相同。仍有明显长帧，不能承诺五角色稳定 60 FPS，也不能把单轮 CPU 差异当作固定收益。相同主机的后台负载、动作相位和窗口合成均有波动。
最初探索轮与测试编译重叠，且部分画布尺寸不同，未纳入表格；原始输出仍保留。对照记录及脚本位于工作区 `artifacts/performance-0.2.13/`（不提交生成物）。

## 正确性与缺失动作

- presentation_tests：帧时钟、移动预测、拖动锚点、RGBA/BGRA 精确转换、透明帧以及奇数宽高/Alpha 阈值附近的 2×2 命中区域检查通过。
- Shiroko 固定 Cafe_Idle 0.5 秒姿势：新旧 PNG 的 RGBA 像素完全一致，尺寸 192×320。此项不代替用户对动态多角色画面的视觉核对。
- 默认启动成功、不创建 logs；诊断启动有性能记录。旧日志不会被自动删除。
- 用户提供的 Nonomi.glb 通过实际加载器检查：27 段动作、81 个采样姿势。该文件缺少 Cafe_Idle、Cafe_Walk、Formation_Pickup。现有咖啡厅回退为 Normal_Idle / Move_Ing，拖动只能保留待机；未强行把 Public01/TSS_Interaction 映射为拖拽。

## 后续精度档位

完成以上对照后新增省电（1×）、均衡（1.5×）、清晰（2×）选项，默认清晰，设置由所有角色共享并保存。只改变内部 FBO 的超采样倍率，最终 DIB 分辨率和窗口坐标保持原值。均衡的内部像素数约为清晰的 56%，省电约为 25%（未触及纹理尺寸上限时）；这不是总开销或帧率提升比例。
按用户后续要求，此功能只构建打包，未继续执行测试或性能测量；上表不能用于比较这些档位。
