# ba_cafe_lite（Three.js）

独立可执行文件：`build/three/desktop_pet_three.exe`。默认直接加载原始 Hibiki.glb，可在中键菜单导入其他自包含 GLB。旧版 `build/desktop_pet.exe` 和其模型、设置保持独立。所有显示角色共享 `build/three/settings.ini`；历史模型路径、显示勾选和各自咖啡厅／战斗模式保存在 `characters.json`，Groot2 XML 保存在 `behavior/角色名.bt.xml`。首次启动兼容旧 `active-model.ini`。

## 运行

双击新的 exe，或执行 `./tools/start-three-pet.ps1`。启动脚本日志为 `artifacts/three-live.log` 和 `.err`。

- 左键点击播放反应；左键拖动、右键旋转、滚轮缩放。
- 中键打开共用网页设置；标题显示选中角色的文件名（不含扩展名），顶部可拖动，关闭叉 / Esc 关闭设置。线条可选无／轮廓／线条三种，滑条调节粗细，贴图里的原有线条始终保留。
- `Ctrl+Alt+Shift+Q` 关闭当前选中角色；最后一个角色会确认后退出。`Ctrl+Alt+Shift+L` 为全部角色切换鼠标跟随。
- 继续使用 C++ BehaviorTree.CPP / Groot2 XML，包括空闲后散步、直线返回起点、追踪鼠标和跨屏移动。

## 咖啡厅 / 战斗模式

中键菜单选择模式，与 raylib 共用 `src/pet_battle.h` 状态机和 `src/pet_battle_input.h` 输入事件。
按关键词识别动作，忽略大小写、空格、下划线、标点和角色名前缀。支持 Normal / Default / Combat、Stand / Standing、Kneel / Crouch，以及 Attack / Shoot / Fire、Start / Begin、End / Stop、Delay / Ready 等常见词。歧义匹配记录警告并跳过，不任意选择不同动作。
导入时先按动作词附近的编号划分整套动作：支持 `Normal01/02`、前置 `01_/02_`、`Normal_Attack01_Ing`、末尾编号，并区分 Tank、Riding、ST / B_ST 家族。默认选择一套具有 Idle + Attack 的连贯组，优先普通人形、默认 / 01 组；不随机混用编号模式。公共动作可复用，无编号且存在编号替代项的动作仅作为默认组动作，不借用另一个编号组的起手 / 收尾。特殊家族和备选组写入映射日志，挂件 / 载具可见性仍需用户验收。
已覆盖 Wiki 清单中 Eimi (Battle)、Hoshino (Battle / Swimsuit)、Kurumi、Toki、Shiroko＊Terror 等编号动作；独立 EX 多版本选择一段完整代表动作，不将 EX Idle / Spawn / Destroy 等阶段或召唤物作为完整技能。有限拼写别名包含 Ilde、Callsigh、Strat、Destory。完全同名的动作仅在时长、通道名、插值和所有关键帧数据一致时去重，否则记录歧义并跳过。名称核对结果见 `design/WIKI_ANIMATION_AUDIT.md`，不代替视觉验证。
有同组 Idle 和实际攻击动作即可启用该姿态；缺失起手/收尾动作时跳过，缺失 Attack_Delay 时使用同组 Idle，缺失 Move_End 时回到同组 Idle，缺失移动动作时不散步。没有 Jump 时不检测交界；缺失的可选姿态不参与随机切换。
Hibiki 没有可用战斗攻击动作，按钮禁用；原始 Azusa / Iori GLB 可直接启用战斗，无需 Blender。未知名称并不保证能自动识别。
每次导入的映射与缺失/歧义记录在本版本 `behavior/角色名.animations.json`，原 GLB、骨架、材质和动作名称保持不变。
没有可用动画时仅静态显示，不运行战斗和自主行走，并记录警告。
包括随机短走/无输入行走、姿态切换、输入攻击和换弹、概率技能、拖拽打断、窗口关闭胜利结算、
战斗三连击死亡与上升退场后回咖啡厅；咖啡厅三连击进入战斗（仅支持战斗的模型），只影响被点击角色。规则和初始参数见 `../../design/BATTLE_MODE.md`。
Three.js 的后续规则：初始 / 姿态 Idle 按一次键即可准备并执行一次攻击；Attack_Delay 按一次键立即攻击，无需持续输入 3 秒。换弹键优先执行 Attack_End → Reload → Idle，缺少 End 时直接 Reload。
Vital_Retreat 渲染朝向为当前朝向 +180°，不逐帧累加，回咖啡厅时恢复正常朝向。
本版状态图为 `experimental/three/design/battle-mode.drawio`、`battle-mode.mmd`，运行目录 `build/three/behavior/` 同步副本；可用 `tools/export_behavior_diagrams.py --three` 重新生成。raylib 保留原规则。
各角色模式保存到 `characters.json`，其余参数共用一份 settings.ini。打开设置时暂停全部角色的行为及移动，正在 Jump 时先完成落地。

Three.js 默认战斗速度 2.376、咖啡厅速度 0.792 世界单位/秒，再乘角色缩放倍率；战斗为咖啡厅的三倍。咖啡厅不使用 Jump。战斗跨屏/可见窗口时提前起跳，交界处为 Jump 动作中点，全程按原方向移动且只播放一次；没有 Jump 的模型跳过边界检测。起跳前检查其他角色占位，落地前保持路径。Attack_Delay 的退出条件为网页设置中的无键盘输入时间，默认 10 秒，鼠标不重置计时。
边界在起步前检查整段路径和减速后的落点，完整 Idle 范围必须能停在同一屏；无安全方向时不开始行走。内部屏幕接缝和小空隙连续通过，大段离屏路径提前放弃；跨屏跟随固定本轮落点，抵达后再规划鼠标位置。停止末段的曲线也检查最终位置，避免先进入 Idle 再启动一次停靠。
持续输入采用暂停容忍（默认 2 秒，范围 0.1–10 秒），避免短暂打字间隔清空计时；无输入判定须同时超过容忍时间和无输入等待。动作播放期间的按键最多合并成一个待执行攻击，120ms 请求 debounce，菜单输入不缓存；缺省 raylib 行为不变。
换弹期间不判断键盘输入、不缓存攻击或再次换弹，也不触发持续输入 EX；进入 Reload 时清除前一段收尾里缓存的攻击。动作结束后只响应新的键盘输入。拖拽和强制退场仍保持原优先级。

## 网页设置与鼠标跟随

设置分为“全局”“咖啡厅”“战斗”，角色列表独立为“角色”页，本地 HTML/CSS/JS 复用已有 WebView2 Runtime。参数自动保存到本版本唯一 settings.ini；`--settings` 可在加载后直接打开菜单。允许移动是散步、跟随的总开关；朝向鼠标与行走跟随是两个独立选项。
历史列表最多 15 条，可从列表删除（不删除磁盘 GLB），角色列表保存导入历史，勾选控制显示，圆点选择切换模式的角色，最多同时显示五人；达到上限时新导入仍进入历史。取消显示释放该角色的渲染器（首角色保留隐藏宿主定时器）。关闭最后一个角色必须确认，取消后继续运行，下次启动恢复一个角色。模型依次加载，避免五个文件同时解析。
一个全局输入观察器为所有角色分发事件。鼠标点击时从可执行 callsign 的空闲战斗角色中随机选一人，再按共享概率判断；该动作播放期间其他人不会同时开始 callsign。行走、跟随、返回起点采用本体宽度和缩放后的避让范围，前方阻塞时停止并放弃当前目的地；用户拖拽重叠时允许走开。
角色窗口按脚下位置的屏幕 Y 排序，下侧角色覆盖上侧角色；移动、拖拽不会将上侧角色随意提到最前面，设置窗口始终在角色上方。避让半径扩大为本体宽度与角色高度共同估算的地面范围，并随缩放变化；它独立于跟随的身位单位，跟随距离不因此变大。

开启跟随鼠标后，两种模式在有输入且可行走的空闲状态立即启动跟随，不等待持续输入或走动间隔；输入停止达到阈值后仍可自主散步；打开设置期间仍暂停，关闭菜单后立即规划。保留攻击、换弹、点击、拖拽优先级。最近、最远距离分别可设为 0.5–20 身位，要求最近 ≤ 最远，默认 3 / 5，可设相等值；范围外移动向范围中点，范围内停止。旧版 FollowBodies 迁移为以原值为中点的区间。
咖啡厅使用独立的“咖啡厅追踪鼠标”开关，所有角色共用；开启后，持续输入达到阈值即在可用的空闲状态追踪鼠标，不进行随机抽选，输入停止后结束。该开关与战斗动作朝向鼠标相互独立。旧 AttentionProbability 参数不再使用，保存设置时会删除。平滑方式逐帧转向；30° 方式只在角度差至少 30° 时开始转身，播放 Cafe_Walk，转身目标固定到完成，脚下位置不变；结束后恢复 Idle。点击、拖拽、移动、返回起点和菜单优先暂停视线追踪，避免多个逻辑同时控制方向。战斗 Idle 仍保持朝向，指挥等动作可以朝向鼠标。
持续输入 debounce 固定为 3 秒，不再显示可调字段。全局页集中显示、位置跟随距离及输入／散步参数；咖啡厅页放视线追踪开关及转身方式；战斗页放动作朝向、EX／指挥概率和收枪时间。持续输入时间的说明区分咖啡厅视线追踪与战斗短走／EX 概率尝试。页面顶部“说明”展示两种模式的主要触发条件。角色列表的“统一大小”立即将显示角色缩放设置成当前众数，同数量取首先加载角色的值，并保存历史。

一个身位使用导入时角色本体的蒙皮宽度：优先统计躯干 / 头部权重且处于身体高度区间的顶点，剔除手持武器、挂件及少量离群点；缺少可靠蒙皮时用肩膀骨骼或高度比例回退。不会使用整套武器 / 长发外包围盒，原 Azusa 约 1.584 单位改为本体约 0.633 单位。距离从身体中心到鼠标计算，按该高度的屏幕投影随缩放换算，不再设固定 20px 的最小身位宽度。

跟随路径每 150ms 更新，实际地面位置仍按 125Hz 积分，接近终点平滑停下。屏幕边界和单屏停留优先，角落或错位屏幕布局可能无法满足设定距离。没有行走动作时跟随选项禁用；拖拽 / 旋转后等待 2 秒才重新跟随。

战斗跟随也预测屏幕和实际可见窗口交界，交界处为 Jump 动画中点。有 Jump 且落点可达才检测和起跳；缺少 Jump 或咖啡厅模式时正常走动。起跳后冻结移动方向、速度和鼠标目标，动作不循环，只播放一次；跨屏路线完成后再重新规划。普通键盘、窗口关闭和设置暂停等事件等待落地，拖拽 / 旋转、战斗三连击可强制取消。跟随停止 / 关闭移动在落地后生效。

| 参数 | 默认 | 生效规则 |
| --- | --- | --- |
| 无输入等待 input_idle | 60 秒 | 两模式自主行走门槛 |
| 持续输入 continued_input | 30 秒 | 咖啡厅转向、战斗短走 / 技能尝试门槛 |
| 走动间隔 | 8 秒 | 两模式空闲后的自主走动等待 |
| 走动距离 | 3 身位 | 战斗有输入时为 50%，偏向远离鼠标；咖啡厅向上仍保留原距离倍率 |
| EX 技能概率 | 5% | 战斗持续输入时按门槛间隔尝试 |
| 点击指挥概率 | 10% | 战斗鼠标点击且有对应动作 |
| 无键盘输入收枪 keyboard_idle | 10 秒 | Attack_Delay → Attack_End |

已有的用户值继续保留，表中默认值仅用于新设置文件和“恢复默认参数”。网页参数覆盖对应 Groot2 节点参数；咖啡厅其他行为仍读取可热加载 XML。战斗图是设计文件，不是可直接运行的 Groot2 树。

## 已合并的平滑过渡

用户确认过渡效果后，平滑功能已成为普通版 `build/three/desktop_pet_three.exe` 的默认行为。使用 `tools/start-three-pet.ps1` 启动。旧试验版目录保留用于回溯，之后重新构建该目标也使用当前实现；不必同时运行两版。

默认优先播放模型已有 Attack_Start / Attack_End / Move_End；从当前显示姿势混合到下一动作，最长 0.18 秒，包含骨骼与面部 morph。缺失目标通道回到原始默认值；混合被打断时从当前中间姿势接续，不手工改骨架。固定动作预览仍直接采样，便于核对原模型。

战斗移动结束时仍播放整段 Move_End，但桌面上的额外位移改为根据该模型、该姿态的脚部运动减速。在导入时用 Three.js AnimationMixer 以约 60 Hz 采样两只脚/脚趾的世界位置，检测接近地面且持续稳定的支撑脚，估计站稳时点与支撑脚后移距离。速度曲线从进入停止动作的步速平滑接续，以测得的距离限制总位移，最迟在支撑脚站稳时降到零；后半段蹲下、举枪或身体调整继续原地播放。放大倍率同时缩放实际停止距离。

这是基于脚部轨迹的保守估算，并非 IK 或精确脚锁定。采样仅在导入时进行，所有节点 TRS 与 morph 都完整恢复；原 GLB 和运行中的骨骼、材质、表情采样保持原样，不使用逐帧脚部反馈调整方向/位置。左右脚命名不明确、无可靠接触样本或缺少 Move_End 时，采用 0.28 秒的短平滑减速。每个停止动作的采样曲线记录在 `behavior/角色名.animations.json` 的 `stopProfiles`，日志记录站稳时点、估计距离与旧距离，便于视觉核对。

咖啡厅散步仍使用最后 0.7 秒的原有减速，直线返回起点保留靠近终点时的减速。Jump 全程保持原方向和速度，落地后才应用停止动作；拖拽、三连击等强制打断保留即时响应。共享 Battle 的旧时间减速逻辑继续保持，Three.js 宿主只替换停止段的实际位移积分，raylib 不变。

战斗正常行走的最后 0.45 秒会以平滑曲线转向停止朝向：有输入且允许追踪时，提前采样一次眼睛到鼠标的方向，否则保留当前朝向；接近边界且该方向不可行时也保留原方向。目标在这段移动中固定，沿最短角度转弯，进入 Move_End 后沿同一方向继续减速，停稳时不再次追随鼠标。Jump 保持原有直线移动，拖拽和旋转可取消转弯。

胜利结算全过程朝向屏幕。模型加载、材质、骨骼 / 表情采样沿用已确认平滑版，不修改 GLB。此前逐帧范围反馈方案的快照仍保留，当前不使用该方案。

显示范围只在导入时计算：采样已映射动作的蒙皮顶点范围并留出余量，用空闲姿态的固定范围约束放置。原生透明窗口在导入、缩放及屏幕布局变化时按动画范围准备尺寸，播放动作不再反复扩缩窗口。窗口透明部分允许延伸到屏幕外，拖拽按角色投影约束，可将头顶拖至屏幕可用区顶部。范围采用有限采样和余量，特别极端的新模型仍需实际动作验收。

空闲前若角色范围跨越两个屏幕，以一次固定目标的行走停靠进入一个屏幕，再恢复原空闲姿态。没有行走动作或禁用移动时一次放置；正常行走仍可跨屏，交互可取消停靠。空闲播放和角色旋转不会反复推移地面锚点。

窗口翻越按桌面 Z 顺序检查，排除隐藏、最小化和 DWM cloaked 窗口，并过滤被前面的窗口遮住的边缘；只检测露出的原窗口边框，不把遮挡切口当作跳跃边界。使用系统矩形及窗口区域，特殊窗口的逐像素透明度和圆角仅作近似，未引入额外框架。DWM 属性见 [微软文档](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute)。

## 模型显示与线条

Three.js 0.185.1 通过 GLTFLoader 直接读取原始 GLB，保留多个 skin、完整节点动画、三次样条和 morph。切换动作前恢复默认 TRS 与 morph 权重；按 Wiki 的方法把网格组上的 morph 动画分发到各 primitive。

采用 Wiki 的不受光照影响的贴图材质，保留颜色、贴图、透明度、双面与 alphaTest。线条模式使用各 mesh 的反向外壳、平滑挤出法线和骨骼/morph 变形；使用黑色，并根据相机 FOV 调整屏幕粗细。轮廓模式对完整角色渲染 alpha 做屏幕空间外缘描边，不添加内部部件描边；无模式禁用额外描边。粗细滑条为默认宽度的 10–300%。原贴图内的线条不会被抹除。

参考源码与固定版本见 `design/WIKI_MODEL_REFERENCE.md`。原始文件不会修改；加载流程不运行 Node、Python 或 Blender。

## 平台与构建

需要 Windows 10/11 x64 和 WebView2 Runtime。本机已安装 Runtime；当前未在干净 Windows 上测试。程序采用 Win32 + WebView2 DirectComposition 透明合成，不显示浏览器窗口，不需要网络服务。Three.js、加载器和两个工具模块随程序放在 `app/three`，离线使用。SDK只用于编译，运行时使用微软 WebView2Loader.dll。

```powershell
./tools/setup_three_pet.ps1
cmake -S . -B build -DBUILD_THREE_PET=ON
cmake --build build --target desktop_pet_three -j 4
./tools/start-three-pet.ps1
```

角色渲染使用 Three.js / WebGL；raylib 仅复用已有地面投影数学，C++ 继续运行行为树和设置数据，网页显示设置。

透明区域通过渲染 alpha 生成 Win32 窗口区域，以支持其他进程窗口的鼠标穿透。读回图像长边最多 480px，再映射到原生窗口，间隔至少 32ms，边缘保留约 4px 容差；尺寸或动作代次变化时丢弃旧读回。拖拽/旋转期间已有鼠标捕获，暂时移除裁剪区域并停止读回，松手或取消捕获后恢复区域。WebView 的背景一直透明。

拖拽窗口在鼠标事件中立即移动。使用 8ms 高精度可等待定时器与单调高精度时钟，目标位置更新 125 Hz；不可用时回退普通 Win32 定时器。浏览器每帧按速度补间位置，校准消息延迟，最多预测 32ms 且不越过本段行走终点；暂停、拖拽和固定姿势预览时关闭预测。
投影的近远裁剪面与 Three.js 相机保持一致，避免拖拽坐标误差。小窗口最多 2x 超采样，较大窗口降低采样倍率以限制 GPU 开销，保留浏览器 MSAA，目标 60 FPS；实际帧率依硬件和窗口可见性而定。

当前支持普通自包含、有动画的 GLB；未接入 Draco、KTX2 解码器或外部资源。没有对任意 GLB 的视觉兼容性作保证。用户负责完整动作的视觉核对。

测试模式（不保存当前模型，截图完成自动退出）：

```powershell
./build/three/desktop_pet_three.exe --model "C:/path/model.glb" --clip Cafe_Idle --sample 0.6 --snapshot "C:/path/review.png"
```

固定动作运行 12 秒后退出，可用于资源采样：

```powershell
./build/three/desktop_pet_three.exe --model "C:/path/model.glb" --clip Cafe_Idle --sample 0.6 --duration 12
./experimental/three/measure-resources.ps1 -RootProcessIds 12345 -Seconds 6 -Output "artifacts/resources.json"
```

资源采样需读取系统进程和 GPU 性能计数器。报告合计包含 WebView2 子进程；`privateCommitMiB` 是私有提交内存，`workingSetSumMiB` 的共享页可能重复计数。CPU 是采样区间的平均值，GPU 是另一次瞬时采样，不能据此认定耗电差异。

本机两阶段资源比较与数据范围见 `experimental/three/PERFORMANCE.md`。

日志每 3 秒记录 FPS、状态接收频率、帧间隔 p95、每帧 JavaScript 时间，以及 alpha 更新的平均耗时/频率。异步 alpha 耗时包含等待，不等于主线程阻塞时间。


缩放和切换模式会取消当前移动及位置预测，并保留脚下位置和朝向。放大后若角色越过屏幕边界，只做一次必要的位置修正。角色原始 GLB 仍按既有方式归一化到 2.3 单位高度，历史列表另外保存各角色的显示缩放；启动时所有角色采用已开启角色的缩放众数，新导入角色采用当前显示角色的缩放众数（按百分位合并，数量相同时取列表中先出现的值）。旧历史文件没有缩放字段时按 1 处理。

持续输入和战斗空闲等待使用真实经过的时间，动画与移动仍使用有上限的帧时间。Three.js 主机另外轮询按键状态，补足低级键盘 Hook 可能失效时的按下事件；不记录输入文本。换弹期间依旧忽略键盘决策。概率设置保留原值，例如 EX 概率为 1% 时达到持续输入时间只进行一次 1% 抽样，不保证播放技能。

被角色或不可通过的边界阻挡时立即取消当前目的地，保持位置和朝向，不绕行或反复尝试同一目标。被挡住的鼠标跟随在鼠标位置改变超过 16 像素、重新开启跟随或手动操作后才会重新规划；已提交的跳跃仍连续播放完成。


GLB 部件显示读取模型 `extras.optional` 和动作 `extras.show/hide`，按照 Wiki 默认隐藏 optional、再 hide、最后 show 的顺序执行。动作切换恢复默认显示状态，不修改骨架或源文件。泳装 Hoshino 的 switch0/switch1 和普通 Hoshino 的 prop0 均走这套通用规则。导入范围只测量可见部件，刻意停放在角色数个身高之外的武器不扩大桌宠窗口；仍保留原始动画变换。初始化异常会结束加载进度并显示原因，不再停在最后一步。

Three.js 在 AttackStart、Attack、AttackDelay、AttackEnd 记录换弹请求，回到攻击空闲／完成收尾后执行；换弹播放期间不再记录键盘请求。咖啡厅散步和战斗走动按共享“走动等待随机幅度”“走动距离随机幅度”在基础参数上浮动，默认 ±10%／±15%，设为 0 可关闭。等待时间每次进入空闲抽样、距离每次起步抽样，原 raylib 默认规则不变。


持续输入触发的战斗短走从身体中心计算移动方向，优先正向远离鼠标，不再随机走近；直接方向不可走时只尝试远离方向 ±15°/30°/45°，都不安全则不出发。移动前段保持远离朝向，最后 35%（最多 0.45 秒）开始曲线转向，沿脚部采样的减速路径继续转弯，停下时与最终切线同向、朝向本次固定的鼠标目标。转弯会检查可用姿态的落点和边界。该路线独立于指挥等动作的“朝向鼠标”开关；位置跟随仍按全局距离设置运行。


滚轮缩放不再重启静止角色的当前动画，也不改变透明窗口尺寸／裁切原点。导入时按最大支持缩放 1.65 预留固定视口；缩放前未完成的鼠标判定结果由独立 maskRevision 丢弃。脚下锚点原样保留，仅放大后确实越过屏幕边界时做一次必要修正。战斗持续输入走动距离为普通距离的 50%，末段曲线比例仍为最后 35%。

画面显示与鼠标判定使用独立的 Win32 窗口。DirectComposition 显示层不设置窗口裁切区域，输入层没有可见绘制表面，仅使用异步 alpha 区域接受点击。这样低分辨率判定图和旧动画帧不会裁掉发丝、光环或快速移动的边缘；两个窗口同步位置及前后顺序，捕获鼠标时仍可拖动到轮廓之外。

显示层同时使用 WS_EX_LAYERED 与 WS_EX_TRANSPARENT，保证实际鼠标输入穿透到其他进程；仅返回 HTTRANSPARENT 或调用 WindowFromPoint 不能替代这项跨进程输入验证。透明画面仍由 DirectComposition 输出，不使用颜色键或 CPU 位图更新。
